# Local model completion recovery

Pinned local Gemma is the explicitly authorized development substitute for NEAR AI. It follows the same owner consent, count, budget, encrypted-cache and original-transaction guards. Local execution does not establish Cloud/TEE attestation or a provider invoice.

The native local grammar is unchanged. Its schema selection now shares `app/model_schema.py` with the Cloud request formatter: only the first trusted system prefix selects a fixed business/app/goal/menu/repair schema, with the existing generic JSON default. The adapter checks any supplied standard `response_format` against that trusted selection; user/source text cannot supply a different schema. Cloud requests use strict `json_schema` for those known prefixes and `json_object` otherwise, but live Cloud schema enforcement remains unverified without a live account. Local image and audio pipelines remain explicit local implementations; this shared text formatter does not implement Cloud image/audio inference.

Typed model parsing accepts only a raw JSON object or one whole `json`/untyped Markdown fence, rejecting commentary, multiple/partial fences, duplicate keys and nonfinite numbers. Existing semantic and authority validators still run. Parsing never rewrites the saved answer or encrypted commitment, and eligible cache replay performs no inference. New text requests include the full serialized `json_schema` format in their conservative input reservation; the fixed generic JSON hint fits within the existing 256-token framing allowance. Longer input may be denied under the unchanged 4608-token ceiling. Cloud truncation, model/role mismatch, tool/function calls or refusal are rejected, retaining unknown/no-retry behavior; no local or Cloud cap is increased.

After provider-envelope and usage validation, the client encrypts the answer and atomically saves the exact encrypted cache and its SHA-256 while the call remains `unknown`. Typed application validation remains a separate step. Only after staging can it submit `ai_complete_call`. A staging or fsync error prevents that completion submission. This does not eliminate the interval between receiving a response and durably staging it: a crash there can still leave an unrecoverable unknown.

For an uncertain completion, first preserve the original worker journal and reconcile its exact pending transaction hash using the existing operator workflow. Never resubmit the signed transaction or issue another inference request. An operator holding the existing configured `NearAIClient` or `LocalModelClient` can then call `reconcile_staged(call_id)`. This explicit API only reads the existing `ai_call` commitment, verifies/decrypts the staged cache, and atomically promotes the local record after a matching completed commitment. It returns metadata, not the private answer. Ordinary cached use still passes the original policy and idempotency checks.

The method never calls transport, reserve or complete. Reserved or mismatched commitments, malformed caches and legacy unknown calls without a staged response remain unresolved. Do not clear their ledger, release their count/reservation or substitute a new model response. The original failed call `33e934…` has no saved response and cannot be recovered by this change.

Reconciliation does not invent a completion receipt or zero fee. If `complete_tx` is unavailable, transaction fees remain explicitly incomplete/unknown even when the exact encrypted output can be recovered. This API grants no account, signing or deployment authority and creates no hosted service.
