# Bounded static web repair

`executor/web_engineering.py` repairs an owner-approved set of HTML, CSS and browser JavaScript files, then runs an independent, immutable acceptance description in real Chrome. A passing proposal becomes a local Git commit. It never pushes or deploys a site.

This broadens the existing pure numeric Python repair executor. It is a static web source path, not a general server/application engineering sandbox. The retained component demo uses a deterministic synthetic edit, explicitly without a model/provider call. Real model execution and NEAR task authorization must be evidenced separately when the runtime connects this adapter.

## Owner policy

Call `repair(scope, client, task_id, registry)` using the existing typed `engineering_patch` scope. The `engineering` reference contains only `repository_id` and SHA256 of the canonical owner policy JSON. A separate registry file must be private, owned by the local user, and contain exactly `{"repositories":[policy]}`.

The dedicated repository must be a canonical, private local Git directory owned by the user. The executor refuses remotes, filters, includes and custom Git configuration. It requires a clean worktree, a pinned initial revision that remains an ancestor, regular tracked non-executable files and no symlinks. Candidate files are copied from Git; the model/browser never receive the original repository or its `.git` directory.

Example policy structure (replace every placeholder with the owner's actual values):

```json
{
  "id": "studio-web",
  "root": "/absolute/private/owner-approved-web-repo",
  "base_revision": "<40-character initial Git commit>",
  "editable": ["styles.css", "app.js"],
  "read_only": ["index.html", "auth.js", "config.json", "acceptance.json"],
  "entrypoint": "index.html",
  "acceptance": "acceptance.json",
  "acceptance_sha256": "<SHA256 of exact trusted acceptance bytes>",
  "public_files": ["index.html", "styles.css", "app.js"]
}
```

The owner selects secret-free static source and assets. Common private key/token formats are rejected before copying or model submission; this bounded check is not a universal secret detector. Only editable source and failed browser metrics go to inference. Authentication, configuration, tests, credentials, wallet and related path names must remain read-only. Files omitted from `public_files`, including the acceptance file, are never served by the preview. Do not approve private data as a public asset.

Bounds: at most 6 editable and 8 read-only files, 12 public files, 128 KiB per asset and 256 KiB per selected snapshot. Editable text totals at most 12 KiB; the complete inference request has a separate 8 KiB bound. Editable extensions are `.html`, `.css`, `.js`. Read-only assets may additionally be JSON, text, Markdown, SVG, PNG, JPEG, WebP or GIF.

## Independent acceptance and edits

The acceptance file is a SHA256-pinned JSON description, not a model-generated test or executable harness. It selects 1–3 viewports (320–1440 by 400–1000 pixels) and 2–16 checks. Supported checks are horizontal overflow, element visibility, text substring, minimum element box size, element count, fill and click. A visual layout and visible-content check are mandatory. Each viewport also checks unapproved requests, unhandled page errors, dialogs and downloads. Browser JavaScript is exercised by the trusted checks; it is never imported or evaluated by Node.

```json
{
  "version": 1,
  "viewports": [{"width":390,"height":844}],
  "checks": [
    {"kind":"no_horizontal_overflow"},
    {"kind":"visible","selector":"h1"},
    {"kind":"box","selector":".card","min_width":250,"min_height":200},
    {"kind":"click","selector":"#book"},
    {"kind":"text","selector":"#status","contains":"A local session has been selected."}
  ]
}
```

The trusted inference system prefix is `Repair the approved web source`. Its only allowed answer is:

```json
{"edits":[{"path":"styles.css","old":"width: 1200px;","new":"width: min(100%, 720px);"}],"reason":"Keep the card inside the viewport."}
```

Each edit changes one exact unique occurrence in an approved existing file. There may be at most four edits; old and new strings each have a 2,000 character bound. Extra fields, arbitrary commands, dependency installs, added files, protected paths and secret-like generated bytes are rejected. No source-selected commands, package scripts, Node routes, server code or dependency resolution are executed. The baseline must fail; the same acceptance must pass after repair. An already passing baseline produces a no-change receipt and calls no model.

## Mandatory macOS boundary

This version supports only the verified local macOS `/usr/bin/sandbox-exec` backend, installed Chrome and the already installed trusted Playwright package. Unsupported hosts or any failed isolation probe fail closed. There is no unguarded fallback.

The outer inherited OS profile restricts regular-file data reads to the copied workspace, the installed Chrome/Playwright bundles, explicit OS libraries/resources and the resolved Node executable/dynamic libraries. It does not merely deny `/Users`: private data in `/private/var/folders/.../T` is also outside the allowlist. Writes are restricted to fresh browser scratch and evidence output, with `/dev/null` permitted. Copied source, acceptance, controller and configuration cannot be written by the isolated processes.

Network access is denied except one selected loopback TCP port and Unix sockets inside the fresh browser workspace. A fixed trusted controller serves only pinned public static bytes, permits GET/HEAD, applies a restrictive CSP and blocks non-allowlisted browser requests. The source selects neither the HTTP routes nor any commands. No source-selected service worker, frame, object, external resource or form submission is allowed. The Node controller uses `--openssl-config=/dev/null` and a minimal environment; the browser has fresh profiles and no host keys or account cookies.

Every actual browser run first proves all nine boundaries:

1. Node cannot read a fresh canary in a separate private OS temp directory.
2. Node cannot write the copied source.
3. Node cannot write the trusted harness configuration.
4. Node cannot connect to a listening second loopback port.
5. Node cannot connect to the external address `1.1.1.1:443`.
6. The fresh Chrome page has no Node `process`, `require` or `Buffer` bindings.
7. Chrome cannot navigate to that private temp file.
8. Chrome cannot navigate to the listening second loopback port.
9. Chrome cannot navigate to the external address.

The approved local preview must also actually load. A timeout or inconclusive denial never counts as a successful probe.

**Explicit limit:** Chrome's inner Chromium sandbox is disabled because its nested seatbelt renderer crashes under this inherited profile. The verified outer OS profile is mandatory for the controller and browser descendants. Directory/device metadata and OS system services remain outside the regular-file confidentiality claim. This is not a VM, TEE, container, hostile same-user isolation or Chromium zero-day defense. If stronger isolation is required, this executor must wait for a separately verified backend.

## Evidence and crash recovery

Full manifests retain exact source SHA256 values, acceptance SHA256, trusted controller SHA256, OS profile SHA256, process-output SHA256, actual browser version, all nine probe outcomes, every viewport check, screenshot SHA256/byte count, and local base/candidate Git commits. PNG bytes and JSON manifests live in the private `.git/proofwork-web/evidence/<task-hash>` directory. Screenshots reflect actual rendered bytes after the trusted interaction checks.

The encrypted task receipt is compact: it includes test totals, nine probe outcomes, screenshot identities, acceptance/controller hashes, source-manifest SHA256, local commit and SHA256 of each exact full `before-browser.json`/`after-browser.json` manifest. It lists up to four failed checks with bounded numeric geometry metrics; the detailed manifests retain every check. This keeps the existing 6,000 byte plaintext/8,192 byte envelope limits unchanged. Oversized summaries fail before creating a Git candidate. Consumers must verify each detailed manifest against its receipt hash before expanding its checks or source identities.

The source, trusted controller and configuration are rechecked after Chrome exits. A model cannot lower the acceptance or substitute a zero-test result. Both before and after screenshots remain available even when an incorrect repair is rejected; a failed proposal leaves the repository unchanged.

Successful verification is journaled durably before an atomic Git HEAD compare-and-swap. Restart finalization reuses the tested candidate without another model call. Concurrent source changes, protected-file changes, unrelated staging and untracked files are preserved by refusing finalization. No reset, checkout, hook, public push or remote access occurs. A committed retry returns its historical receipt after confirming the commit is still an ancestor; it does not claim that later owner edits still pass.

Run the focused tests and retain a component demo using the project's configured Python environment:

```sh
.artifacts/venv/bin/python -m unittest executor.test_web_engineering -v
.artifacts/venv/bin/python scripts/demo_web_engineering.py
```

The component fixture starts with a 1,200 pixel card overflowing both approved viewports. A synthetic bounded CSS edit fixes the measured defect; all 18 real Chrome checks, including a browser-JavaScript button interaction, pass afterward. The script retains mobile/desktop before and after PNGs, exact implementation hashes and an explicit `model_calls: 0` report. This component proof alone is not evidence of a complete public business workflow, cloud inference, NEAR authorization or public deployment.

`node integration/web_engineering_e2e.mjs` is the separate actual-model integration. It creates a fresh local NEAR company, submits one exact encrypted owner-approved `engineering_patch`, caps inference at one call per job/day plus a durable one-call transport gate, uses the existing pinned local Gemma adapter, verifies the compact receipt against full Chrome manifests, recovers the encrypted result using its exact private recovery file, and retains the local Git repository. A wrong recovery key must fail. Restart, archival and idle checks must not call inference again. The first integrated attempt exposed the oversized-receipt boundary after a real model repair and passing browser verification; its failed-run artifact remains separate from later attempts. No automatic inference retry or expanded encryption/contract bound was used to address that defect.
