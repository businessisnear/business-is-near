# Native source watch and editorial review

This workflow observes literal public data from exact owner-selected NEAR contracts. A finite signed watch reports added, changed and removed records, queues a separate encrypted editorial task, and links an archived draft to a separately approved public-page revision. Observed bytes, owner assertions and draft claims remain unverified. It does not discover the whole market, verify competitors' claims or infer business outcomes.

Open `/native-watch.html` from the owner workspace. Connect the actual testnet company owner and authenticate the existing private owner service. Choose a watch ID, owned editorial publisher and one reviewed source account. The browser supports a current public page or public feed; the CLI supports up to eight explicit source accounts. Review the policy and sign the read-only NEP-413 challenge. Source code, genesis and account IDs are pinned. The editorial publisher cannot watch itself.

The host configuration is the existing protected `executor.private_workspace_server` configuration: fixed RPC/genesis and company-code allowlist, no browser-selected URL or filesystem path. Its guarded `/__private/native-watch/<action>` routes require the existing same-origin, CSRF and current FINAL FullAccess owner authentication. All chain proofs are collected on that owner host. An arbitrary browser-supplied proof is never accepted as RPC evidence. The host imports no wallet/operator/provider private credentials, signs no transactions and calls no models.

Click **Observe once** to collect one later FINAL snapshot. There is no background polling in the interface. The signed policy permits at most eight observations and an optional interval of up to 3,600 seconds. The private CLI can execute a finite number of polls explicitly; an incomplete read attempt is retained and halts automatic retries. Each selected contract must still run a reviewed local WASM template. Company owner and signer access are rechecked at the same FINAL block. Public page observations expose only the enabled current version; feed observations expose the enabled bounded post prefix. A disabled source produces a removal from this projection, while its immutable onchain history remains public. Each raw record is bounded to 64 KiB, each prefix to 64 records and 1 MiB, the combined observed raw projection to 1 MiB, and differences to 128 records. Oversize, duplicate, mixed-block, truncated, foreign-code or changed-owner inputs fail closed.

Queue the chosen source report, then review **a separate draft**. The current interface prepares an ordinary `content_draft` task with `use_ai:false`: source extraction, with no model response or semantic research claim. The Python API may explicitly prepare `use_ai:true` scopes for a separately configured, capped existing model policy; the watch signature itself never authorizes a model. Exact source account, raw-byte digest, change ID and report digest stay in the encrypted task scope. Keep the downloaded owner recovery file private. Binding checks the real owner-approved task, encrypted scope, current company and source-change scope. After the ordinary worker archives it, linking checks the encrypted evidence, exact source digests, artifact and mandatory claim-review receipt. Recovery keys are used in memory and are not stored in the editorial event journal.

Refresh the source after draft archival. A newer changed source invalidates that draft for publication. Load the original recovery file, select the next public-page version, and review the rendered static page. The content is escaped and previewed in a sandboxed frame. Publication requires three separate explicit consents: this exact page is public and nonsecret, the owner has publication rights, and permanent public history plus retained storage are approved. A fresh native quote binds active-version compare-and-swap, exact HTML and record digests, storage price and owner. The wallet alone signs the actual `publish` call. Nothing publishes from watching, queueing or drafting.

The owner host saves the original publication intent before dispatch. Unknown wallet results block new publication intentions across the queue. Enter only the original wallet transaction hash and reconcile it read-only. The host checks the entire FINAL receipt graph, actual fees, exact signer/receiver/action/arguments/deposit/gas, and the stored native revision. It never resends the transaction. The public HTML includes the source-change and report digests; its native source reference binds company, archived task and encrypted evidence digest. Old public versions remain readable. A lost wallet result with no known hash requires inspecting the original wallet history; it is not permission to retry.

The protected CLI entry points are:

```sh
node scripts/native-source-watch.mjs
python -m executor.native_source_watch --root /absolute/private/watch init
python -m executor.native_source_watch --root /absolute/private/watch watch
python -m executor.editorial_queue --root /absolute/private/editorial --watch-root /absolute/private/watch entries
```

Each command accepts a bounded exact JSON object on standard input; no key belongs in a command argument. Node commands are `prepare`, `collect`, `record`, `quote` and `receipt`. Python watch commands are `init`, `append`, `history` and `watch`; editorial commands are `queue`, `entries`, `scope`, `bind-task`, `link-draft`, `render`, `prepare-publication`, `mark-broadcast` and `confirm`. New private roots must already be owner-only canonical directories. The authenticated HTTP adapter derives paths itself and validates watch IDs before creating any directory. The CLI's explicit `append`/proof APIs are owner-host integration primitives: their containers require trusted RPC collection; they do not independently prove blockchain consensus.

Only fixed `public_page` and `feed` source projections are supported. Knowledge, directory, native service/CRM requests and arbitrary contracts or URLs are not silently included. Customer request metadata is not inferred to be competitor research. This scope is distinct from the thirteen-family complete company exit. Current-state observations require a trusted RPC and provide no light-client proof, deleted history, universal fact checking, global account discovery, SEO or audience guarantee.

Observation budgets belong to the retained private host journal; public NEAR reads are permissionless, so this is not a global onchain quota. The owner interface rejects responses above 3 MiB. Large histories can therefore require owner review through the bounded private CLI rather than loading in the interface. No automatic retry, source expansion or summary inference occurs after that refusal.

Offline verification is `python -m unittest executor.test_native_source_watch` and `node --test scripts/test_native_source_watch.mjs`. The functional harness is `integration/native_watch_editorial_e2e.mjs`: it uses actual isolated local NEAR and synthetic public source data, changes an independently owned source across snapshots, archives an encrypted NoAI draft, publishes one separately approved signed revision, reconciles the original hash without a second broadcast, and verifies old history remains. Reports are written under `.artifacts/native-watch-editorial/<run>/report.json` with exact source pins and teardown. An authored harness is not a passed run; check its actual report. No public deployment, real Cloud account, model call or business outcome is established by this NoAI proof.
